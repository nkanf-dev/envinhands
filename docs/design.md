# EnvInHands 详细设计：机器与 Agent 协作网络

> 交接设计，以**目标体验、契约与演进方向**为主体；除第 14 节明确标为现状外，本文是待实现或待验证的设计，不代表现有代码已经具备该能力。团队可信并不意味着网络可信。当前原型不能用于生产或直接暴露公网。

## 1. 背景、愿景和边界

三位异地成员有六台设备：Linux desktop、Debian NAS、一台 Windows、三台 Mac。设备分处不同网络，可能在 NAT 后、没有公网入站地址、休眠或动态换网。每人可运行多个 Prime Agent，也可能以不同 SSH 身份访问。期望每台机器由所有者一次明确授权后加入共享网络；成员和 Agent 能找到合适的机器、建立 SSH、判断近期活动、交换消息与经验，网络变化后恢复工作。

设计不止限定于 MVP。长期可把多团队、多种设备及计算资源接入可扩展网络，让 Agent 自主发现资源、协商使用、分享经验，结合本机知识和网络状态选择路径。但首要落地对象仍是三人和六台设备；跨团队属于演进方向，身份治理、数据边界和部署方式要另行确认，不能隐含现有共享 token 足以支持陌生团队。

**已确认目标**：注册成功即目标 Agent 的 SSH 登录和非交互管理员能力得到实际验证；多入口自动探测、排序及失败回退；Agent 跨机发现、通信与经验共享；远端 tmux；兼容零公网 IP/NAT 节点；Bun/TypeScript 对接 Prime Agent TS 0.9.8，可复用 Rust；提供 Agent skills；服务支持 `0.0.0.0` 监听；开发以 main 和 conventional commit 为协作约定；不要 CI。

**非目标**：不提供团队内部用户权限分层、进程/文件/网络隔离或资源独占保证。留言、申请、Agent 协商和资源意向不是锁或预约。团队管理员访问可读取或破坏整个系统；参与者必须理解风险并自行协调。非目标不取消 SSH 认证、主机密钥校验、网络加密及凭据保护。零公网 IP 是指**节点无需公网入站**，不表示在完全无共同可达路径或无任何中继设施时必然连通。

## 2. 用户体验与完成含义

1. 节点所有者在本机启动注册，确认共享账号、团队公钥、管理员权力、暴露的 SSH 服务和撤销方式；私钥、管理员密码不上传。系统预览变更，明确可能授予无限制管理员能力，明确确认后才应用。
2. 节点主动建立一个或多个出站入口并上报候选；控制面创建 pending 记录。为每个需要访问的 Agent，以该 Agent 自己的 SSH 登录身份，通过已信任的主机密钥与目标路径实际执行非交互登录和管理员验证。仅当**目标 Agent 身份**通过且结果未过期，界面才可说该 Agent 的注册成功/ready；服务自身的检查只能证明服务身份，不能推出所有 Agent 成功。
3. 用户或 Agent 按 OS、架构、能力、近期状态和经验搜索；展示验证时间、每身份就绪、节点与路径的实时性及未知状态。选择机器后自动尝试可用连接，不改变 SSH 安全检查，失败列原因和建议。
4. Agent 可以显式发送消息、主动拉取或经有界通知接收待处理消息，独立确认处理；资源备注、经验和消息视作不可信内容。它们协助人和 Agent 共享上下文，不构成对远程机器的锁或权限授予。
5. 在远端可用时启用 tmux 会话，重连后重新附着。网络恢复不代表 SSH 原连接迁移，也不保证中断期间命令完成；工具必须显示结果未知并要求核对。

优先保证语义诚实：不可达、尚未验证、失效、未知和忙碌分开；不能用“已登记”或“心跳存在”替代“当前身份可以登录并具备管理员权限”。

## 3. 技术架构与组件边界

```text
             人/Prime Agent 0.9.8 (多台设备、多个 Agent)
          +-----------------------------------------------+
          | skills: 发现/连接/协作流程、安全和故障处理    |
          | extensions: 活动/消息/资源工具；本机 SSH 客户端|
          +----------+--------------------------+---------+
                     | HTTPS API                | SSH + 本地代理
                     v                          v
         +----------------------+    +------------------------------+
         | Bun/TS 控制与消息面  |    | 路径选择/连接编排器          |
         | 目录/验证/经验/队列  |    | 新鲜探测 -> 排序 -> 失败回退 |
         | SQLite 或未来存储    |    +-------+-----------+----------+
         +-----------+----------+            |           |
                     |               直连/私网        出站反向连接
                     |                                v
                     |                  +---------------------------+
                     |                  | 中继/外部隧道服务         |
                     |                  | 成熟 Rust 后端或其他工具  |
                     |                  +-------------+-------------+
                     |                                ^ 节点主动出站
                     v                                |
         +-----------------------------------------------------------+
         | 目标节点：轻量 agent/隧道进程 + OS 适配 + OpenSSH server |
         | 可选 tmux（Unix）; 本机批准管理员访问；SSH 端到端        |
         +-----------------------------------------------------------+
```

控制面管理目录、身份验证证据、协作和策略，不承载 SSH 明文；数据面只做字节通道，不实现 SSH 或执行未认证 shell。节点只访问本机明确配置的 SSH 端口，不允许中继请求指定任意内网目标。SSH 客户端直接验证主机身份并完成用户认证；跨多路径不能关闭验证。

Bun/TypeScript 适合与 Prime 的 TS 运行时、扩展、快速迭代和现有 HTTP/SQLite 契约整合。节点希望轻量、少依赖，可复用成熟 Rust 二进制（如 rathole/wstunnel）或按结果开发小型 Rust sidecar；TS 通过受限进程参数、配置文件或本地 API 管理生命周期。取舍是两个运行时、版本与多架构构建、进程监督、第三方许可及安全配置成本；Bun 单文件打包包含运行时，不等于 Rust，也需逐平台测试。先验证协议、故障和授权，不自研 SSH。最终后端选择、静态/动态链接与二进制大小待性能、许可、安全及部署验证。

## 4. 核心模型及一致性

以下是目标逻辑模型，并非声称已有全部字段和数据库表。

| 实体 | 核心信息 | 规则 |
|---|---|---|
| Machine | 稳定 ID、名称、OS/架构、资源清单、SSH 账号、主机公钥指纹、所有者、登记时间 | 机器是资源容器；网络地址变化不应变更身份；指纹更换需带外确认。 |
| Agent | 唯一 ID、所属机器/会话、可选能力、最近观察时间 | 一机多 Agent；身份标签与认证能力分开，未知不等于空闲。 |
| AccessEvidence | machineId、agentId/SSH 身份指纹、路径、检查时间、到期、结果及失败分类 | 只反映该身份该时刻的登录和管理员能力；默认 5 分钟到期、随变更或失败提前失效；不保存私钥。 |
| Endpoint | 节点、后端、地址引用、配置状态、最近探测及时间、失败域、成本/延迟 | 支持多入口；敏感凭证仅存受保护密钥库；状态可过期。 |
| Resource/intent | 稳定 ID、类型、属性、位置、关系、状态、意向及时间 | 可扩展 CPU、GPU、存储、工具、工作区；声明、心跳及估计不保证可用或独占。 |
| Message | requestId、发件/收件 Agent、正文或引用、创建/确认时间 | 幂等发送、允许重复处理；接受不代表送达或执行。 |
| Experience/note | 资源引用、作者、版本/时间、内容、来源、可信度和可选失效时间 | 记录经验，不当作命令或事实保证；不自动含密钥。 |
| Session | machine/Agent、稳定会话键、tmux 名称、路径、最后确认、恢复状态 | 是对远端会话的引用，不是已恢复 SSH 或命令结果的承诺。 |

用稳定 ID 连接对象，显示观测时间及来源；时钟漂移、过期、重启后陈旧与并发写入须有明确处理。拟使用服务端接收时间和单调时钟判定本地超时；跨节点时间仅作参考。经验和消息需要容量、分页、保留期、删除与导出设计。动态资源申请可定义 request/offer/accept/cancel/expire 和超时，显示协商结果及冲突，但在当前非隔离前提下只是意向，不能保证独占或调度成功；是否引入租约语义需单独决策。

## 5. 注册、配权与逐身份验证

目标状态机及失败路径：

```text
new -> pending -> 本机预览/确认 -> 应用公钥与管理员配置 -> 验证
                                                             |
                       验证通过且对应身份未过期  <------------+
                       ready(agentId, identity, checkedAt, expiresAt)
                             | 过期/失败/身份或配置变更
                             v
                       stale/not-ready -> 重验或撤销
任一阶段拒绝/异常 -> failed 或 partial，列出已变更项目与可审计恢复指引
```

**注册成功**是按 Agent/SSH 身份的事实，不是单个笼统机器布尔值。默认 5 分钟是证据的新鲜度窗口，不是五分钟访问租约或持续可达保证。验证过程中旧结果先失效；并发检查使用版本或随机 token，旧结果不得覆盖新结果；重验的时间和错误可见。服务执行一次 SSH 验证只证明**服务的 SSH 私钥身份**；若所有 Agent 的密钥不同，必须分别通过实际路径验证。不能根据服务端验证推导所有 Agent 已 ready，也不能收集它们的私钥到服务。应让各 Agent 在自己的运行环境完成挑战，或设计可审计的委托验证；防伪证据和各身份撤销协议待决定。

目标本机授权流程：在目标节点解析已有账户和真实 home，预览新增的公钥、sudo/管理员权限和回滚，获得所有者明确确认；检查安全目录、文件所有权、权限和符号链接，保留其他 authorized_keys。Unix 使用最小必要且经确认的 sudo 策略，若需求是全管理员，应明确其为无限制 root；验证 SSH 的严格主机密钥检查、非交互公钥登录及 `sudo -n true`。Windows 使用已配置的 OpenSSH 和非交互 PowerShell，验证**当前 SSH 会话实际有效管理员令牌**，而非仅组成员身份；UAC、不同 shell 和系统策略必须在真机实测。默认拒绝未知平台和验证错误。

安全 apply 必须防目录遍历、符号链接和并发替换；用受控文件描述符、原子无覆盖写入、`visudo` 验证准确内容、适当持久化及崩溃恢复；授权和 sudo 文件不是天然事务，部分失败须列可见状态。撤销只移除本次实际新增且未被其他人修改的内容，不破坏原有条目。macOS 和 Windows 分别设计，不能复制 Linux sudoers 实现。**当前自动安装、配权和安全撤销尚未实现；Unix 检查及 Windows 实际令牌代码不能仅凭 mock 宣称跨平台实测。**

## 6. 多出口、NAT 与连接生命周期

目标是节点主动向可达入口出站，同时收集多个可配置候选：局域网/已存在的 VPN 直连、rathole 或 wstunnel/frp 等反向隧道、UU 官方或第三方能力、必要时独立中继；不要求所有节点有公网 IP。候选优先级可由团队配置，建议按直连/私网、可验证的自有反向入口、其他已授权入口排列，再结合新鲜健康探测、延迟、成本和共同故障域动态调整。用户可覆盖顺序；不得声称某后端目前已接通。UU 第三方 Linux 软件和网络服务需独立验证平台、许可证与服务条款。VPN、云入口或端口映射不自动等于 SSH 安全或可达。

连接状态建议为 `unknown -> probing -> healthy/degraded/failed -> stale`；禁止把进程启动等同于连通。探测有超时、年龄上限和退避；真正建立 SSH、失败后记录原因，按优先级尝试下一**新连接**；不关闭主机密钥检查。自动回退的总时间预算、重试次数、并发探测上限、路径去抖与冷却须可配置。处于相同服务、账号或网络的入口需标共同故障域。可并行保持多个已认证入口以减少恢复时间，未来可研究主动探测、健康评分、带宽聚合和去中心发现；**聚合或无缝迁移是研究项**，普通 SSH 流不能跨后端透明迁移，不能为性能牺牲有序、完整和保密性。

节点主动重连应指数退避、抖动、上限、断开时关闭子通道、停止时清除定时器和子进程。可恢复的是发现与新连接；旧 TCP/SSH 会话中断，写入或远程命令结果可能未知。必须设置并测试最大节点/会话数、握手时间、idle、带宽和排队预算；提供逐连接和全局限额，拒绝过载而不是无限缓存。

数据面须明确双向 backpressure：各方向有限缓冲、高低水位、慢端暂停及解除、写入失败和溢出策略；记录丢弃/中止而非宣称送达。TCP half-close 要支持独立方向 EOF、数据排空及回包，或者明确拒绝依赖该语义的协议；WebSocket 关闭不自动等同 TCP 半关闭，关闭帧、远端 FIN、进程崩溃和排空超时须逐项测试。当前实验 relay 有限额、部分排空但**不支持透明 half-close，不保证关闭后错误可回传**；未达到目标。

## 7. tmux 与远程执行恢复

Linux/macOS 可选择在 SSH 上以稳定、校验过的 session key 创建或附着远端 tmux；应先探测 tmux 和用户环境，缺失时给出安装建议或降级为非持久 SSH，而不是显示可恢复。断线后重新选择路径、验证相同主机、登录并附着同一个仍存活的会话。可并行附着，但要提示多个客户端共享输入和输出。主机重启、tmux server 停止、休眠、shell 杀死都会使状态丢失；tmux 不等于持久作业系统。

未来远程执行可引入明确 job ID、命令摘要、启动时间、状态文件、退出码与结果索引，以便重连时查询；先定义启动请求幂等、任务唯一性、终止与清理、重启和半完成状态。网络断开时标记 `unknown`，不能自动重复执行不可幂等命令；是否重试需应用确认。Windows 原生 tmux 不假定存在，WSL/其他持久会话机制需独立评估及真机验收。

## 8. Agent 发现、消息、资源与经验

心跳只表达一次观察，使用稳定 Agent ID、所属 machine ID、可选粗粒度活动和服务接收时间；默认展示最后观察、新鲜度和 unknown，而非推断在线或空闲。活动采集应显式 opt-in，默认不采集 prompt、工具输入输出、私钥或环境。心跳延迟、乱序和缺失不能用于锁资源。

消息契约：发送者为每个逻辑消息提供唯一 requestId；服务成功仅表示接受存储，不代表读取、处理或执行。同 ID 同内容重试应幂等，冲突返回错误；请求超时结果未知时复用原 ID 和内容。拉取不等于认领，消息可能重复或并行处理；消费者按 ID 持久去重、处理完成后才显式 ack，ack 可重试但不证明正确处理。若将来需要认领、可见性超时、自动通知或 dead-letter，须额外设计并测试，不能将其视为 exactly-once。支持有限分页、保留与容量上限是后续目标。

资源目录可将机器、GPU、存储、网络入口、模型与工具建成有类型和关系的资源图，Agent 根据属性和当前意向发现、提出申请、交换 offer、说明需求和预计完成时间；实际调度和资源隔离不是本阶段承诺。经验共享支持按资源引用、版本、作者、时间、适用平台、来源、过期和反馈搜索，例如依赖安装、故障处理、性能观察。应允许手工纠错、去重、导出和删除，明示历史内容可能错误。所有消息、备注及经验都可能含 prompt injection；接收者视其为数据，受原用户授权与安全规则约束，不自动执行。

Prime Agent 0.9.8 采用显式、opt-in 扩展对接，业务总线独立于 Prime 内部本机消息协议；配置缺失时显式诊断是目标，不能让扩展失败拖垮 Agent。拟提供 `SKILL.md`：列出发现、核对就绪、按 Agent 身份连接、资源申请、发送/拉取/ack、经验共享、失败恢复和安全边界；skill 是 Agent 操作说明，不是服务、认证机制或自动注入。跨机收件通知、自治协商和对本地 session 的安全注入需另定授权、幂等、退出及用户体验；明确来源、保留不可信标识，不自动当指令执行。

## 9. 无中心可用时的降级与生态

中心控制服务失联时，已建 SSH 连接是否存续取决于实际数据路径；已有健康直连或独立中继路径可继续供新连接使用，但单点 relay 失联会断开其会话。节点与客户端可缓存已验证的主机公钥、候选、上次验证与经验；缓存带来源和有效期，过期显示 stale/unknown，不能据此冒称当前管理员就绪。可在本地配置已知对端经 SSH 直接连接，在用户知晓过期证据和风险下工作；无路由时明确失败，不保证离线消息实时送达。

未来可研究节点间签名目录、局域网/mDNS 发现、P2P/QUIC、跨多个中继的 rendezvous、存储转发或离线队列和合并。需先决定信任根、密钥撤销、重放防护、冲突解决、时钟漂移及离线队列丢失与重复语义；去中心不是无信任、无单点或 NAT 穿透必然成功。跨团队联邦、资源描述 schema 版本、扩展接口及外部生态可逐步试验，参与者自愿交换资源和经验；不把用户已排除的团队内部权限隔离列成首版强依赖，但外部边界的身份和数据保护不可省略。

## 10. 安全、故障域与可观测性

- 允许 `0.0.0.0` 作为显式监听配置；它意味着所有 IPv4 接口而非权限控制，也不是客户端地址。生产建议默认受限监听并在网络边界设防火墙。HTTP/WS 的 token、消息和元数据在明文链路可被窃取和修改；不可信网络使用经过验证的 HTTPS/WSS，包括代理到后端链路；代理和日志不能泄漏 token 或正文。
- 初期共享 bearer token 便于三人使用，但持有者可冒充 Agent、读他人队列、ack 消息；共享 relay secret 可冒充节点或访问节点。TLS 不解决这些问题。安全分发、保护环境和配置、轮换、撤销与事件响应必须设计；不要把密钥放进仓库、命令行或本文。长远可用每节点凭据、短期证书和签名证明身份，不把角色隔离设为产品前提。
- 信任 SSH 主机公钥通过带外确认；不上传 SSH 私钥/管理员密码，不跳过 host key。目录/备注/数据库、SQLite 备份及临时文件可能敏感，应限制权限、加密和设保留期。共享管理员意味着泄密后高影响。
- 初期单服务、SQLite 文件和中继均为单点；多个后端若共用网络、服务器或账号，也可能一起故障。先做数据库备份、恢复演练、磁盘容量和人工重启手册；HA 和复制仅在语义清楚后实施。
- 拟提供结构化、脱敏日志和度量：验证身份/结果/时间、节点与路径最后观察、重连数和耗时、路径失败原因、活跃会话、速率/缓冲/超时中止、消息积压及最旧未确认年龄、DB 磁盘与备份状态。按匿名或安全 ID 关联，禁止原文、凭据和 SSH 流；告警、保留与可视化尚待实现。

## 13. 测试策略与待决问题

本地使用 `bun test`、`bun run typecheck`；Rust 原型用对应目录 `cargo test`，涉及注册的测试须用隔离临时目录和 mock，不得触碰真实 sudo 配置。并发、数据库损坏/满盘、消息重放、数据大小和陈旧值需自动化；真实平台验收则在授权的六台设备、不同网络和休眠场景进行，记录环境、身份、观测时间及失败，不保存密钥。

待团队决定：目标 SSH 身份清单及授权是否为无限制管理员；验证证据由 Agent 如何可信提交；默认安全监听和代理部署；实际后端顺序、入口与共同故障域；需要多少离线能力和保存时长；资源申请冲突与通知方式；Windows 持久会话；自动消息注入的授权边界；跨团队身份与数据共享。每项均不可因“代码存在”自动视作决定。
