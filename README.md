## 项目定位

EnvInHands 是一个供三人团队使用的远程机器协作工具的初始设计。团队成员身处不同地点，使用不同平台，需要共同了解机器、连接状态、Agent 活动和资源相关的留言。

**当前为实验性原型，不可用于生产或直接暴露公网。** 已有部分 TypeScript 组件与测试，但它们尚未整合成完整可运行产品；本文同时包含目标、现有原型和待确认设计。

## 设计目标

- 让团队成员可以发现已登记的机器，并可靠地通过 SSH 连接。
- 提供共享视图，帮助成员了解机器和 Agent 的活动情况。
- 允许成员围绕机器或相关资源留言，补充使用意图、状态和注意事项。
- 为与 Prime Agent TS 0.9.8 对接预留设计空间。
- 兼顾团队成员使用的不同客户端平台，以及远程机器可能存在的平台差异。

这里的“资源”指团队协作中需要描述或讨论的机器及其相关资源。具体资源类型和展示范围尚待确认。

## 使用场景

1. 成员登记一台团队可访问的机器，其他成员查看其连接所需信息。
2. 成员通过 SSH 连接机器，在连接失败或中断时获得清晰反馈，并在条件允许时恢复工作。
3. 成员查看机器上已知的 Agent 活动，判断是否有人或 Agent 正在使用相关资源。
4. 成员在相关资源下留言，例如说明正在进行的工作、使用计划或需要其他人注意的事项。
5. 成员结合留言和活动信息，自行协调机器和资源的使用。

## 功能设计

### 机器注册与发现

- 支持登记、查看和维护机器信息，使团队成员能够识别目标机器。
- 记录连接所需的信息，并展示可用的连接状态或最近一次检查结果。
- 明确区分登记信息与实时状态；状态可能过时或不可用，不应被当作可用性的保证。
- 具体字段、状态采集方式及机器下线后的处理方式待确认。

### SSH 连接

- 以 SSH 为远程连接基础，考虑异地网络不稳定、连接中断和重连等情况。
- 向用户说明连接中、成功、失败或中断等状态，以及可用的错误信息。
- 重连时不得暗示中断期间的操作一定完成；远程会话能否恢复取决于实际环境。
- 支持安全地处理身份凭据和主机身份验证。凭据存储、传递和信任策略尚未确定，不应在设计阶段假定具体实现。
- 客户端和远程机器的具体平台支持范围待确认。

### Agent 活动

- 展示能够获取的 Agent 活动，并尽可能关联到机器和相关资源。
- 活动信息应有可理解的时间或新鲜度提示；无法获取或已过时的状态应明确标识。
- 展示范围、数据来源、更新方式及历史保留范围待确认，不能假定能观察到所有活动。

### 资源留言

- 成员可以围绕机器或相关资源发布和查看留言，用于协作沟通。
- 留言应能识别关联对象、作者和时间，便于理解上下文。
- 留言是协作提示，不是锁、预约或权限控制，也不保证资源独占。
- 编辑、删除、通知和历史保留等行为待确认。

### Prime Agent TS 0.9.8 对接

- 以 Prime Agent TS 0.9.8 为目标对接版本，探索获取和展示相关 Agent 活动的可行方式。
- 先核实该版本实际提供的接口、事件和运行环境，再确定集成边界与兼容性方案。
- 本文不假定其存在特定 API、插件机制或活动数据格式，也不承诺对接能力已经可用。

## 范围与边界

- 面向三人团队协作；不设计用户权限体系或按用户限制操作的权限控制。
- 不提供机器、进程或其他计算资源的隔离，也不提供资源配额或独占保证。
- 第一版可按操作系统等条件查找机器；不承诺预留、独占或复杂资源调度。成员依靠活动信息和留言自行协调。
- 以上边界不意味着可以忽略 SSH 身份验证、主机验证或敏感信息保护。
- 机器注册、连接状态、活动和留言的共享方式，以及数据的持久化方式尚未确定。

## 待确认问题

1. 已知节点包括 Linux desktop、Debian NAS、Windows 和三台 Mac；各平台需要支持哪些 SSH 认证方式？
2. 机器信息由谁维护？连接地址变化、机器退役和不可达时如何处理？
3. “可靠连接”的目标是什么？断线后的重连、会话恢复和错误反馈有哪些最低要求？
4. 哪些 Agent 活动和资源需要展示？允许多长时间的状态延迟？
5. 留言是否需要编辑、删除、通知或历史保留？数据放在哪里？
6. Prime Agent TS 0.9.8 的实际集成能力和接口是什么？是否需要支持其他版本？
7. 团队如何安全地共享连接信息，并处理凭据和主机身份验证？

## 可复用注册、修改记录与远程执行

EnvInHands 自身提供不可变 Agent 注册和追加式修改记录，支持幂等重试、分页、离线本地持久队列以及显式同步。普通 Agent 可用 CLI，不要求改 Prime 平台；Prime 可从本仓库加载独立 opt-in 适配。署名是声明，不是密码学认证；显式记录不代表已自动捕获任意工具或外部程序的所有修改。见 [修改记录](docs/change-records.md)。

`src/transports/ssh-routes.ts` 将既有策略接到真实严格 SSH 探测，在有限总预算内按优先级尝试候选，保持同一受信主机别名。`src/remote-execution.ts` 在受控入口执行前持久记录 intent，执行后追加结果；一旦命令开始，不因失败或超时自动换路重跑。`exec` CLI 只执行用户授权的命令，远程输出是不可信数据，不是新授权；它不自动配权或保证远端任务断线后完成。

## 当前状态

当前代码包含 SQLite 消息与机器目录服务、实验性 SSH 反向中继与 CLI、传输选择、UU/rathole 进程适配、管理员就绪检查和 tmux 命令构造。Prime Agent fork 的 `main` 已有 opt-in 心跳、消息和资源工具。旧 Linux 开发环境曾通过隔离的真实 OpenSSH 和 Prime 心跳/消息扩展加载器测试；这不是当前 Windows 环境或资源扩展的加载验证，跨机器与公网尚未验证。自动配置公钥与 sudo、多后端自动连通和 tmux 的实机恢复验证仍未完成；Windows 管理员检查已有 mock 测试，尚未实机验证。

`src/server.ts` 提供的机器、资源留言和 Agent bus API 使用共享 bearer token，但没有内置 TLS；持有 token 的任何人均可冒充 Agent、访问队列和修改目录。独立的 `src/control.ts` 内存原型没有认证或 TLS，不是该 SQLite 服务。实验性中继仅使用共享 secret，存在明确的流控与关闭语义限制。**不要将原型直接暴露公网，也不要以此作为生产连接通道。** Agent 管理员就绪要求见 [架构草案](docs/architecture.md)，连接方案及其状态见 [候选清单](docs/transports.md)。

本地开发需要 Bun。在仓库根目录执行 `bun install`、`bun test` 和 `bun run typecheck`。测试包含本地 socket 与 mock；通过测试不意味着跨机器、跨平台或公网已验证。

详细的实验性 CLI 使用与限制见 [快速开始](docs/quickstart.md)。也可单独启动实验性 Agent 消息服务：

```bash
# 先在当前 shell 安全设置 ENVINHANDS_TOKEN；不要提交 token。
# 仅首次生成；安全保存这个值，所有节点须使用同一 token，重启时继续使用。
export ENVINHANDS_TOKEN="$(openssl rand -hex 32)"
export ENVINHANDS_DB="./envinhands.sqlite"
bun run src/server.ts
```

HTTP 默认绑定 `0.0.0.0:8787`；可通过 `ENVINHANDS_HOST` 和 `ENVINHANDS_PORT` 修改。此服务**没有内置 TLS**，会暴露共享密钥和消息内容；非可信网络必须通过正确配置的 HTTPS 代理访问，不能直接暴露到公网。它目前提供机器元数据、资源留言、Agent 心跳与消息队列 API；机器登记只是保存信息，不会安装 SSH 公钥、配置 sudo，也不提供 SSH 通道或 Agent 自动注入。
